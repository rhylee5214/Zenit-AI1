# ZENIT data policy

ZENIT never trains on data without a recorded license and your explicit permission.

## Manifests

Every dataset build and fine-tuning run reads a manifest in `data/manifests/`. Each source lists:

| Field | Meaning |
|---|---|
| `name` | Short identifier |
| `path` or `hf_dataset` | Local file or folder, or a Hugging Face dataset id (`hf_config`, `hf_split` optional) |
| `kind` | `text`, `jsonl_text`, `chat_jsonl` or `pref_jsonl` |
| `license` | The license you checked on the source |
| `origin` | Where it came from |
| `permission` | Must be `true`. You set it after reading the license. |
| `weight` | Repeat factor for small important sets |
| `filters` | Per-source overrides for the quality filters |

The loader refuses the whole manifest when any source lacks a license, has `permission` other than `true`, or points at a missing file. It prints every problem at once.

## What the pipeline does to the data

1. Unicode normalisation (NFC) and control-character removal.
2. Whitespace cleanup, with code indentation kept.
3. PII scrubbing: email addresses, phone numbers and IPv4 addresses become `<EMAIL>`, `<PHONE>` and `<IP>`. Switch off with `--keep-pii` only for data you own.
4. Quality filters: length limits, letter ratio, repeated-line ratio.
5. Exact deduplication on normalised text, then near-duplicate removal with MinHash LSH over 5-word shingles.
6. A deterministic train/validation split by content hash.

The build writes `meta.json` with per-source counts, filter reasons, duplicates removed and the manifest fingerprint. The fingerprint travels into every run, model card and registry entry, so each checkpoint traces back to its exact data.

## Data in this repository

| Set | License | Purpose |
|---|---|---|
| `data/raw/zenit_seed/` | CC0-1.0, original | Pipeline proof for ZENIT 0.1. Identity, arithmetic, facts, honesty, simple code, conversation. |
| `data/sft/zenit_persona.jsonl` | CC0-1.0, original | Identity, honesty and style examples for fine-tuned versions |

Scripts in `scripts/` regenerate all of these.

## Open datasets to consider

The example manifests list these with `permission: false`. Read each dataset card yourself, since licenses and subset terms change, then switch permission on.

| Stage | Dataset | License listed on its card at the time of writing |
|---|---|---|
| SFT | `HuggingFaceTB/smoltalk` | Apache-2.0 |
| SFT | `allenai/tulu-3-sft-mixture` | ODC-BY-1.0, with per-subset terms |
| DPO | `HuggingFaceH4/ultrafeedback_binarized` | MIT |
| Pretraining (ZENIT 1.0) | `HuggingFaceFW/fineweb-edu` sample | ODC-BY-1.0, plus Common Crawl terms of use |

Datasets generated by other companies' models carry those companies' terms of use as well. Check them when you plan commercial use.

## Contamination guard

`tests/test_eval_integrity.py` fails when any evaluation prompt appears in the training corpora, or shares a 10-word span with them. Arithmetic evals use operand pairs excluded from training, and name and fictional-entity evals use lists the training generators skip.
